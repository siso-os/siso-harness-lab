# Ship train

`ci/siso-ci serve` discovers every open PR once a minute. Configured host slots run independently, each with a locked warm clone at `WORK/workers/SLOT/clones/OWNER/REPO`. Long suites do not block discovery. `ci/workers.json` sets workers, allowed repositories and free-space admission per host. The Mini has two slots and delegates eligible harness/Agent Zero jobs to one halo-vps slot over SSH. siso-vps was unreachable on 16 October. HALO remains on the Mini: its `.siso-ci` explicitly requires macOS Postgres/Chrome paths and Node 22. A remote job receives GitHub credentials only through its stdin pipe, never argv or a saved credential file.

Before checkout, the slot takes an OS lock and checks free disk. Under pressure it archives only ignored caches and clean merged worktrees inside its own root, verifies archived file bytes before retiring originals, and prunes stale Git registrations. It never touches operator checkouts or global stores. An insufficient disk remains blocked. Mini runtime clones live on the already-mounted storage vault because its internal data volume reached 100%; archives also stay on the vault. Ignored node_modules remain warm between jobs; tracked dirt blocks checkout, and untracked files are archived. No force checkout or clean.

Every PR posts **siso-ci/pr** on its exact head. Trusted explicit mappings or a package graph select changed packages plus transitive dependents; unknown paths/config/history select the full relevant command. HALO receives `SISO_CI_MODE=affected` and a fetched merge-base, compatible with HALO's separately owned affected-test script. Its existing script safely runs full until that work lands. Vitest-compatible commands can opt into `sharding: {count, min_files, test_glob}`; every shard must pass. HALO's Node suite owns its own sharding implementation. No HALO app/test code is changed here. npm cache writes stay in the worker root on its selected volume.

`ci/ship-train HALO-AGENCY/halo-streaming halo/v2` selects non-draft, mergeable open PRs whose latest **siso-ci/pr** status on their exact heads is success, sorted by PR number. An optional `train.label` requires that label as well. `gh pr merge --match-head-commit` refuses a moved head. With `train.suite: "nightly"` (HALO, 17 Oct) no suite runs here: the collected head ships because every PR in it passed its own gate, and the full suite moves to `--nightly`, report-only (see AFFECTED.md). Without it, one full relevant suite runs on the collected head; intermediate commits are not tested individually. Unchanged green heads skip testing. A per-branch OS lock prevents overlapping trains. `siso-ci serve` (the `com.siso.ci.workers` coordinator) runs this train itself as a child, one per `train.branches` entry, and starts the next `train.every` seconds (120) after the last ended; its record is logged as a `"kind": "train"` line in serve-workers.log. The per-branch lock keeps the older `ci/com.siso.ship-train.plist` (every 1200 s) from overlapping; it is no longer needed and a locked run writes no record. PR discovery skips train-managed trunk branches. This avoids duplicate serial post-merge testing.

A red deterministic result invokes **the existing PR #41 red-main bot**, now parameterized by branch. It verifies both boundaries, bisects first-parent landings, confirms the culprit/parent, tests the revert on fresh trunk and publishes via `land` in PR-only mode. The train validates the recovery PR base/head, merges the tested revert and runs the full suite again. It comments on PRs associated with the culprit. Missing green history, setup failures, timeouts, conflicts, an unsafe kit, ambiguous bisect or a second independent failure stop recovery. Retained recovery worktrees are evidence. `SISO_LAND_BASE` plus gh's per-branch `gh-merge-base` target the proper branch; no direct trunk pushes. A completed recovery receipt is retryable.

Only successful full suites write `WORK/trains/OWNER/REPO/BRANCH/last-green.json` and **siso-ci/train**. A legacy success can be imported only with a successful full branch-run receipt, first-parent ancestry and a still-green GitHub `siso-ci` status. The hook rechecks the train status/ancestry and receives the exact `SISO_CI_SHA`; it never resolves deployment from moving HEAD. HALO's reviewed `ship-head.sh` accepts no SHA and follows HEAD, so its underlying `bash v2/deploy/ship.sh "$SISO_CI_SHA"` is used instead. Existing box build/release health, room and rollback gates remain authoritative. Failed/refused deployments do not update `deployed.json`; the next train retries the same green. A red train deploys its preceding green before starting a potentially long bisect.

Each invocation appends `minutes-lost.jsonl`: queue wait, test execution, bisect/recovery wall time, deploy execution, PRs in/dropped, test exit/runs, head, last green and deploy outcome. Heavy admission waits are read from heavy's admission receipt and separated from execution. `latest.json`, `running.json`, private test/deploy logs and exact statuses are the operational evidence. Test logs are mode 0600; raw output is not copied into PR comments.

GitHub returned HTTP 403 for HALO branch protection on 16 October (private-repo plan restriction). The train enforces its own gate; it cannot prevent a manual bypass on this plan. No privacy or billing setting changed. Separate lane-A PRs #53-55 and HALO #470/#473 overlap the affected/trunk areas; this train retains the affected-mode interface and supersedes serial branch scheduling only for its configured branch.

Proof: `heavy -- node --test tests/ship-train.test.mjs tests/red-main.test.mjs tests/ci-affected.test.mjs tests/siso-ci.test.mjs`. Fixtures exercise real Git merges/reverts, parallel slot overlap and exclusion, preserved warm files, recoverable cache archival, package dependencies/full fallback, shard failure, exact-SHA deployment and retained green after red. GitHub/land are replaced at the fixture publication boundary. Live adoption and HALO timings are recorded separately; fixture success is not live green/deployment evidence.

For a rolling upgrade, `com.siso.ci.workers.plist` starts the new parallel coordinator separately while the legacy service drains. A root coordinator lock prevents two upgraded daemons from dispatching. Disable legacy auto-start only after confirming the new service; no operator/test process is killed.

Mini launchd returned `PermissionError: [Errno 1] Operation not permitted` on the removable vault, while the same command worked under SSH. Both production LaunchAgents therefore invoke the command through a verified **127.0.0.1 SSH session**; no new listener or external connection is added. A dedicated Mini-only `siso-ci-loopback` key is restricted to loopback and has forwarding/PTY disabled; the host key is pinned from the Mini's own SSH host public key. The private key never leaves the Mini. HALO access uses a separate Mini-generated restricted `siso-ci-halo` key, with a verified host key and the existing shaan account. SSH/config/authorized-key changes were backed up before additions. This preserves the vault isolation under the already-authorized Remote Login context without requesting privacy UI access.

A failing head must fail twice in one train before anything is bisected (a flaky test is green and ships, `"flaky": true`); a recovery that finds the head green on the fresh run promotes it. A head that failed its full suite on two trains (three for timeouts and infrastructure) is left alone, recorded in `heads.json` and shown as `known_red`, until the branch moves; a recovery step marked retryable is never given up on.

**HOLD.** A file named `HOLD` in the train's directory (`WORK/trains/OWNER/REPO/BRANCH/HOLD`) makes the train do nothing: no PR merged, no suite, no deploy (a HOLD set mid-run still blocks the deploy, `deploy_state: held`), and no record written. It is set on the Mini for HALO/halo/v2 while a night streams on DEV (17 Oct); `rm` it and the next train (within 2 min) ships the green head. The old `com.siso.ship-train` launchd job is disabled (`launchctl disable`) on the Mini: the coordinator runs the train now.
